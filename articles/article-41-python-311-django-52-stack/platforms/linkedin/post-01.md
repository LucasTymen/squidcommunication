## Contenu

Quand j'ai choisi la stack technique pour SquidResearch, j'ai opté pour Python 3.11 et Django 5.2.5. Après 6 mois de développement et 50 000 lignes de code, je peux dire que c'était le bon choix.

Python 3.11 apporte des améliorations de performance significatives. J'ai remarqué des gains de 10 à 60% selon les opérations par rapport à Python 3.9. Pour un projet qui fait beaucoup de traitement de données et d'enrichissement, c'est important.

Django 5.2.5 offre des features intéressantes. Les vues async, les nouvelles migrations, les améliorations ORM. J'utilise 83 apps Django avec une architecture modulaire, et Django gère bien la complexité.

Le frontend est en React 19.2.1 avec Next.js 16.0.7. La stack Django REST Framework côté API, React côté interface. L'API compte 83 endpoints, tous documentés et testés.

L'architecture complète inclut aussi Celery 5.5.3 et Redis 6.4.0 pour les tâches asynchrones. n8n et Flowise pour l'orchestration IA. Docker pour la containerisation. Le tout représente 50 000 lignes de code réparties sur 83 apps Django.

La qualité du code est suivie avec des tests. Coverage à 70.59% globalement, avec 97.67% de taux de réussite. Sur les modèles IA spécifiquement, la couverture atteint 94.23%. 58 tests créés, dont 43 unitaires qui passent tous.

Le choix de cette stack était motivé par l'écosystème Python. Celery pour les tâches asynchrones, Redis pour le cache, PostgreSQL pour la base de données. Des outils matures, bien documentés, avec une grande communauté.

Pour le frontend, React 19 apporte des améliorations de performance. Next.js 16.0.7 facilite le SSR et le routing. L'intégration avec l'API Django via REST Framework est fluide.

Après 6 mois, la stack tient la route. Pas de problèmes majeurs, des performances correctes, une évolution progressive possible. Pour un projet qui doit évoluer et grandir, c'est rassurant.
